# 오너 결정 사항 (Decision Log)

AI 직원은 배치를 기획할 때 이 문서를 전략 문서보다 우선한다. 새 결정은 아래에 날짜와 함께 추가한다.

## 2026-10-15 — 시작 방식
- **B(디지털 상품) 위주 + A(AI 보조 외주) 서비스 1개**로 시작한다.
  - 첫 배치: 판매용 디지털 상품 4~5개 + 외주 서비스 등록 페이지 1개.
  - 외주 서비스는 오너가 결과물을 직접 검증·설명할 수 있는 분야(데이터 분석/크롤링/파이썬 자동화 계열)로 한정한다.
  - 디지털 상품은 외주 서비스의 포트폴리오 역할도 하도록 기획한다(예: 크롤링 템플릿 ↔ 크롤링 외주).
- **판매 플랫폼:** 리서치 추천을 따른다 (수수료, 한국 거주자 정산 가능 여부, 경쟁 상황 근거).
- **오너 시간 예산:** 주 2~3시간 (업로드·승인·문의 응대). 이보다 많이 드는 운영 방식은 제안 단계에서 표시한다.

## 2026-10-15 — 수요조사 기반 생산
- 남는 직원은 실시간 수요(크몽 신호, 검색 트렌드, 시즌 캘린더, AI·자동화 수요)를 조사해 다음 배치를 정한다. 결과는 비공개 저장소 `products/_private/trends/`(보고서 `<날짜>_수요조사.md`, 브리프 `next_briefs.json`, 시즌 급한 것 `urgent_briefs.json`)에 둔다.
- **배치를 기획할 때(클라우드 정기 실행 포함)** `products/_private/trends/next_briefs.json` 에 아직 생산되지 않은 브리프(트래커 products.csv 에 같은 id 가 없는 것)가 있으면, 리서처 스캔 대신 그중 시기가 급한 순서로 최대 3개를 `company-run.js` 의 `briefs` 인자로 넘긴다. 없으면 기존처럼 리서처가 아이디어를 낸다.
- 수요 근거는 측정치(순위·리뷰 수·지수·날짜 있는 공지)와 추론을 구분해 적고, 근거가 약한 기회는 생산하지 않는다.

## 2026-10-15 — 게시 전 점검 시점
- 생산·준비 단계에서는 게시 전 점검(소속·보험·세무상 제약 확인)을 미룬다. 수익이 생기지 않는 단계이기 때문이다.
- **첫 상품의 게시 승인 요청(`publish_listing`)을 올릴 때**, CEO 는 READY_FOR_OWNER.md 맨 위에 "게시 전 점검 완료 여부" 체크 항목과 질문 목록 위치를 넣는다. 점검 기록이 없으면 게시를 권하지 않는다(결정은 오너).
- 질문 목록과 점검 기록은 개인 사정이 들어가므로 비공개 저장소(`products/_private/02_게시전_점검_기록.md`)에만 둔다.
- CEO·CFO 는 게시 승인 요청과 장부 기록 때 이 비공개 기록을 읽고, 그 안의 "직원이 지킬 것"을 따른다(예: 첫 매출 시 오너 알림).
