# 시스템 인터페이스 계약 (모든 부서·스크립트 공통)

이 문서는 회사(AI Revenue Engine)를 구성하는 파일들이 서로 맞물리기 위한 **고정 규약**이다. 바꾸면 대시보드·트래커·워크플로가 함께 깨지므로, 바꿀 때는 이 문서부터 고친다.

프로젝트 루트: 저장소를 체크아웃한 폴더 (이하 `ROOT`, 다른 문서의 `<프로젝트 루트>` 표기와 같다). 스크립트는 환경변수 `AIRE_ROOT`, 없으면 `scripts/` 의 부모 폴더를 ROOT 로 쓴다.
런타임: Python 3.12 표준 라이브러리만 사용 (pip 설치 금지). Node 24 사용 가능.

## 1. 직원(Role) ID

| role id | 부서 (오피스 방) | 한국어 직함 | 하는 일 |
|---|---|---|---|
| `ceo` | 대표실 (CEO) | 대표 | 배치 목표 결정, 상품 브리프 승인/반려, 최종 출고 판정 |
| `researcher` | 리서치 (Research) | 리서처 | 수요·경쟁·가격 조사, 근거 URL 수집 |
| `pm` | 기획·디자인 (Designing) | 기획자 | 상품 사양서(spec) 작성 |
| `designer` | 기획·디자인 (Designing) | 디자이너 | 구조·레이아웃·썸네일 브리프·브랜딩 |
| `maker` | 제작 (Coding) | 제작자 | 실제 산출물 파일 제작 (문서·템플릿·코드) |
| `qa` | 검수 (Testing) | 검수자 | 적대적 검수, 실행/열람 테스트, 결함 보고 |
| `marketer` | 마케팅 (Marketing) | 마케터 | 판매 페이지 문구, 키워드, 가격 근거 |
| `cfo` | 재무·법무 (Finance) | 재무·컴플라이언스 | 장부 기록, 세무·표시광고·AI표시 규정 점검 |

병렬로 여러 명이 같은 역할을 맡으면 인스턴스 ID를 `역할-번호`로 쓴다: `maker-1`, `maker-2`, `qa-3` …
대시보드는 `-` 앞부분(prefix)으로 부서 방을 결정한다.

## 2. 오피스 상태 (대시보드가 읽는 것)

### 2-1. 상태 파일 — `ROOT/office/status/<instance_id>.json`
```json
{
  "id": "maker-2",
  "role": "maker",
  "state": "working",
  "task": "노션 취업 준비 템플릿 제작 중",
  "bubble": "💻",
  "product_id": "notion-job-hunt-kit",
  "updated_at": "2026-10-15T14:03:22+09:00"
}
```
- `state` ∈ `idle` | `working` | `meeting` | `blocked` | `done`
- `bubble`: 이모지 1개 또는 6자 이하 짧은 텍스트 (말풍선)
- `product_id`: 선택

### 2-2. 이벤트 로그 — `ROOT/office/events.jsonl` (한 줄에 JSON 하나, append-only)
```json
{"ts": "2026-10-15T14:03:22+09:00", "id": "maker-2", "role": "maker", "type": "status", "state": "working", "msg": "노션 취업 준비 템플릿 제작 중"}
```
`type` ∈ `status` | `handoff` | `decision` | `defect` | `approval_request` | `note`

### 2-3. 직원이 상태를 바꾸는 방법 (유일한 공식 경로)
```bash
python ROOT/scripts/office.py status <instance_id> <state> "<task>" [--bubble "💡"] [--product <product_id>] [--type status]
python ROOT/scripts/office.py event <instance_id> <type> "<msg>" [--product <product_id>]
python ROOT/scripts/office.py reset          # 모든 직원 idle 로
python ROOT/scripts/office.py show           # 현재 상태 표 출력
```
직원(에이전트)은 **작업 시작 시 `working`, 끝나면 `done`** 으로 반드시 바꾼다.

### 2-4. 오피스 서버 — `python ROOT/scripts/office_server.py [--port 8765]`
- `GET /` → `office/index.html`
- `GET /api/state` → 
```json
{
  "now": "...",
  "agents": [ /* status 파일 전부 */ ],
  "events": [ /* 최근 80개, 최신이 마지막 */ ],
  "kpis": { "products_total": 0, "by_status": {"draft": 0}, "revenue_krw_total": 0, "revenue_krw_this_month": 0, "expenses_krw_total": 0, "net_krw_total": 0 },
  "approvals": [ /* approvals.csv 중 status=pending 행 */ ],
  "products": [ /* products.csv 최근 20행 */ ]
}
```
- 표준 라이브러리 `http.server` 만 사용. 127.0.0.1 에만 바인딩.

### 2-5. 대표 명령창 API — `scripts/office_chat.py` (오피스 화면에서 이 PC 의 Claude Code CLI 를 헤드리스로 부른다)
- `GET /` 를 내줄 때 `office/index.html` 의 `__SHREW_CHAT_TOKEN__` 을 서버 프로세스마다 다른 무작위 토큰으로 바꾼다(올바른 Host·같은 출처의 페이지 요청에만. 다른 사이트가 script/fetch/iframe 으로 끌어가는 요청에는 자리표시자 그대로 → 명령창 꺼짐).
- **모든 경로**(`/api/state`·정적 파일 포함)는 `Host` 가 `127.0.0.1:<포트>` 또는 `localhost:<포트>` 가 아니면 403 (DNS 리바인딩 방어). 응답마다 `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'…`, `Cross-Origin-Resource-Policy: same-origin`.
- 모든 `/api/chat*` 요청: 헤더 `X-Shrew-Token: <토큰>` + `Host: 127.0.0.1:<포트>|localhost:<포트>` + (있다면) 같은 출처 `Origin`. 아니면 403. POST 는 `Content-Type: application/json`, 본문 64KB 이하(413). CORS 헤더는 주지 않는다. 오류는 항상 `{"error": "<한국어>"}`.
- `POST /api/chat` `{"message": 1..8000자, "model": "sonnet"|"opus"(기본 sonnet)}` → `202 {"job_id"}` · 이미 처리 중이면 `409 {"error","job_id"}` · CLI 없음 `503 {"error","hint"}`
- `GET /api/chat/jobs/<job_id>` → `{"job_id","status":"queued|running|done|error","text","tools":[{"name","summary"}],"session_id","cost_usd","error","started_at","finished_at"}` (text 는 실행 중에 자란다, 모르는 id 는 404)
- `GET /api/chat/history` → `{"messages":[{"role":"owner|claude|system","text","ts","job_id"}](최근 100개), "cli":{"found","path","logged_in"}, "active_job_id"}`
- `POST /api/chat/reset` → `{"ok": true}` (CLI 세션을 잊는다. 기록은 남고 "새 대화 시작" 줄이 붙는다)
- CLI 찾는 순서: 환경변수 `SHREW_CLAUDE_BIN` → PATH 의 `claude` → `%APPDATA%/Claude/claude-code/<최신 버전>/**/claude.exe` → `~/.local/bin`. 작업 폴더는 ROOT, 자식 프로세스에 `AIRE_ROOT=ROOT`. 제한 시간 15분(프로세스 트리 종료). 한 번에 하나만 실행.
- 권한(`--permission-mode acceptEdits`, 헤드리스라 물어볼 사람이 없어 허용 목록 밖은 모두 거부): 허용 목록은 WebSearch·WebFetch, `office.py`, `tracker.py`(list·report·add-product·set-status·add-ledger·request-approval), 읽기 전용 git(status·diff·log) 뿐이다. 파일 읽기·검색·수정은 **이름만 넣은 허용 규칙을 쓰지 않고** CLI 기본 동작(작업 폴더=ROOT 안만 자동 허용, 밖은 거부)에 맡긴다 — 이름만 있는 `Write`/`Read` 규칙은 프로젝트 밖(사용자 폴더 전체)까지 열린다(실제 CLI 로 확인). 막는 것(deny): `tracker.py approve|reject`, `office.py reset`, `git push|reset|add|commit|checkout|…`, `gh`, `git … --output|--no-index`, `rm`, `del`, 그리고 `tracker/approvals.csv`·`CLAUDE.md`·`.claude/`·`scripts/`·`office/chat/` 직접 편집과 `.env`·`*.key`·`secrets/` 읽기(**승인은 오너만**, 절대 규칙 2). `--setting-sources project,local`(오너의 전역 설정 허용 규칙을 섞지 않음, 필요하면 `SHREW_CLAUDE_USER_SETTINGS=1`) · `--strict-mcp-config`(Gmail·Notion 등 커넥터 미연결). `--resume` 에 넘기는 세션 ID 는 `[A-Za-z0-9._-]` 형식만 받는다.
- 저장: `office/chat/history.jsonl`(추가 전용), `office/chat/session.json`(`{"session_id": ...}`). 둘 다 .gitignore 이고 정적 파일로도 내주지 않는다.
- 작업 중에는 CEO 책상이 `working / "대표 명령 처리 중" / 📨` 로 바뀌고 `note` 이벤트("대표 명령: …")가 남는다. 끝나면 원래 상태로 돌아간다.

## 3. 트래커 (CSV, UTF-8 with BOM — 엑셀에서 한글 안 깨지게)

**위치(오너 결정 2026-10-15):** 매출 장부는 공개 저장소에 두지 않는다. `products/_private/tracker/`(비공개 저장소 `ShrewAICompany-products` 안)가 있으면 그곳, 없으면(새 클론·테스트) `tracker/`. `AIRE_TRACKER_DIR` 로 직접 지정할 수 있다. 경로 결정은 `scripts/_common.py`의 `tracker_dir()` 한 곳에서만 하므로, 직원은 경로를 직접 쓰지 말고 항상 `tracker.py` 를 쓴다. 아래 `tracker/…` 표기는 이 폴더를 뜻한다.

### `tracker/products.csv`
`id,batch,title,model,platform,price_krw,status,created_at,listed_url,notes`
- `status` ∈ `draft` | `in_production` | `qa_failed` | `qa_passed` | `awaiting_owner` | `listed` | `retired`

### `tracker/ledger.csv`
`date,product_id,platform,type,amount_krw,note`
- `type` ∈ `sale` | `fee` | `refund` | `expense` | `payout`
- 매출은 양수, 수수료·환불·비용은 음수로 기록

### `tracker/approvals.csv`
`id,product_id,action,requested_at,status,decided_at,note`
- `action` 예: `publish_listing`, `price_change`, `send_proposal`, `create_account`
- `status` ∈ `pending` | `approved` | `rejected`
- **AI는 approvals 를 `pending` 으로 올리기만 한다. `approved` 로 바꾸는 것은 사람(대표님=오너)만.**

## 4. 산출물 폴더

`ROOT/products/<batch>/<product_id>/`
- `spec.md` (기획), `design.md` (디자인), 실제 산출물 파일들 (제작), `qa_report.md` (검수), `listing.md` (마케팅), `compliance.md` (재무·법무)
- `READY_FOR_OWNER.md` — 오너가 업로드할 때 필요한 모든 것 (파일 목록, 붙여넣을 문구, 가격, 체크리스트)

## 5. 절대 규칙 (모든 직원)
1. 계정 생성·로그인·약관 동의·결제/계좌 정보 입력·금융 거래 금지. 돈은 오너 계정으로만.
2. 게시·발송·제출은 오너 승인 후 오너가 직접. AI는 `approvals.csv`에 요청만 올린다.
3. 허위 수익 보장, 가짜 리뷰, 스팸, 저작권/상표 침해, 무단 개인정보 수집 금지.
4. AI 생성물임을 플랫폼 규정·인공지능 기본법에 맞게 표시. 제휴 링크는 대가성 문구 표시.
